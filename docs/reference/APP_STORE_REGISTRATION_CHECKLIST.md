## 1. 공통 준비사항

### 1.1 필수 자산

| 항목 | 사양 | 상태 |
|------|------|------|

  - 연락처 정보 포함

- [ ] **이용약관** (선택, 권장)

- [ ] **저작권 확인**
  - 사용된 이미지 라이선스 확인

  - 오픈소스 라이선스 표시 (설정 화면)

## 2. iOS App Store

### 2.1 App Store Connect 설정

#### 앱 정보
- [ ] 앱 이름 (30자)
- [ ] 부제목 (30자) - 핵심 가치 전달
- [ ] 카테고리 선택 (1차, 2차)
- [ ] 연령 등급 설정
- [ ] 저작권 정보
- [ ] 라이선스 계약 (기본 EULA 또는 커스텀)
- [ ] **가격 및 사용 가능 여부** — 신규 앱은 가격 티어(무료/유료)와 출시
  국가를 ASC에서 직접 선택해야 출시 가능. `./deploy`는 IAP 상품 가격만 설정하고
  앱 자체 가격 티어는 설정하지 않는다 (Apple 콘솔 수동 단계).

#### 앱 심사 정보
- [ ] 연락처 정보 (이름, 전화, 이메일)
- [ ] 로그인 필요 시 테스트 계정 제공
- [ ] 심사 참고 사항 (특별 설명 필요 시)
- [ ] 앱 내 구매 설명

#### 버전 정보
- [ ] 스크린샷 (6.9" 또는 6.7" 필수; 5.5"는 2024년 폐지)
  > `./screenshot`이 기본 6.9"/13" 사이즈로 캡처. **첫 제출은 스크린샷이
  > 필수**다. `./deploy`는 스크린샷을 기본 건너뜀(`--skip-screenshots` 기본
  > true) — 생성+업로드를 함께 하려면 `./deploy --target production
  > --no-skip-screenshots`로 실행하면 된다. 이 플래그가 deliver/supply에
  > `SKIP_SCREENSHOTS=false`를 주입해 업로드까지 수행한다(별도 환경변수 설정
  > 불필요). 캡처 기기 사이즈가 ASC 허용값(6.9"=1320×2868, 6.7"=1290×2796)과
  > 일치하는지 확인할 것.
- [ ] 앱 프리뷰 (선택)
- [ ] 설명
- [ ] 키워드 (100자)
- [ ] 지원 URL
- [ ] 마케팅 URL (선택)
- [ ] 업데이트 노트

### 2.2 빌드 설정

```
# Fastlane으로 자동화된 항목
bundle exec fastlane build_and_upload_ios
```

수동 확인 필요:
- [ ] 버전 번호 증가됨 (`CFBundleShortVersionString`)
- [ ] 빌드 번호 증가됨 (`CFBundleVersion`)
- [ ] 프로비저닝 프로파일 유효
- [ ] 인증서 만료일 확인 (최소 30일 이상)
- [ ] 아카이브 성공

### 2.3 App Privacy (앱 개인정보)

**필수 입력:** App Store Connect → 앱 개인정보

데이터 유형별 체크:
- [ ] **연락처 정보** (이메일 등)
- [ ] **식별자** (사용자 ID, 기기 ID)
- [ ] **사용 데이터** (제품 상호작용)
- [ ] **진단** (충돌 데이터, 성능 데이터)

각 데이터 유형에 대해:
- [ ] 사용자 연결 여부
- [ ] 추적 사용 여부
- [ ] 수집 목적

### 2.4 iOS 전용 요구사항

- [ ] **ATT (App Tracking Transparency)**
  ```dart
  // iOS 14.5+ 필수
  await AppTrackingTransparency.requestTrackingAuthorization();
  ```

- [ ] **Sign in with Apple** (제3자 로그인 사용 시 필수)
  - Google 로그인 있으면 Apple 로그인도 필수

- [ ] **인앱결제** (해당 시)
  - 앱 외부 결제 유도 금지
  - 인앱결제 상품 등록 및 심사
  > **⚠ 유료 앱 계약 (수익화 앱 필수, 자동화 불가):** IAP/구독을 쓰는 앱은
  > App Store Connect → 계약/세금/금융 정보에서 **유료 애플리케이션 계약**에
  > 동의하고 **은행 계좌·세금 양식**을 작성해야 한다. 이게 안 되면 IAP 상품이
  > "심사 대기" 상태로도 넘어가지 못해 앱 심사가 거부된다. Apple 콘솔에서만
  > 처리 가능한 수동 단계다.
  > **상품 등록 (자동):** `project.yaml`의 `iap.products`/`iap.subscriptions`를
  > 채우면 `./deploy --target production`이 `upload_iap` 레인으로 ASC에 상품을
  > 자동 등록한다(consumable은 ASC 수동 등록). project.yaml의 IAP를 바꿨으면
  > 먼저 `./run iap-register`로 재생성하거나 deploy가 자동 재생성한다.

## 3. Google Play Store

### 3.1 Google Play Console 설정

#### 스토어 등록정보
- [ ] 앱 이름 (30자)
- [ ] 짧은 설명 (80자)
- [ ] 전체 설명 (4000자)
- [ ] 앱 아이콘 (512x512)
- [ ] 그래픽 이미지 (1024x500)
- [ ] 스크린샷 (최소 2장)
- [ ] 카테고리
- [ ] 연락처 이메일
- [ ] 개인정보처리방침 URL

#### 앱 콘텐츠
- [ ] **개인정보처리방침** URL 입력
- [ ] **앱 액세스** 설정
  - 로그인 필요 시 테스트 계정 제공
- [ ] **광고** 포함 여부
- [ ] **콘텐츠 등급** 설문 완료
- [ ] **타겟층** 설정 (아동 대상 여부)
- [ ] **뉴스 앱** 여부
- [ ] **코로나19 앱** 여부
- [ ] **데이터 보안** 설문 완료

| 개인 정보 | ☐ | - |
| 금융 정보 | ☐ | - |
| 건강/피트니스 | ☐ | - |
| 메시지 | ☐ | - |
| 사진/동영상 | ☐ | - |
| 오디오 | ☐ | - |
| 파일/문서 | ☐ | - |
| 캘린더 | ☐ | - |
| 연락처 | ☐ | - |
| 앱 활동 | ☐ 대부분 해당 | 분석 |
| 웹 브라우징 | ☐ | - |
| 앱 정보/성능 | ☐ 대부분 해당 | 크래시 리포트 |

## 4. 심사 리젝 방지

### 4.1 iOS 흔한 리젝 사유

| 사유 | 가이드라인 | 방지 방법 |
|------|------------|-----------|
| 앱 완성도 부족 | 2.1 | MVP라도 핵심 기능 완성 |
| 버그/크래시 | 2.1 | 충분한 테스트 |
| 메타데이터 불일치 | 2.3 | 스크린샷이 실제 앱과 일치 |
| 제3자 로그인만 제공 | 4.8 | Apple 로그인 필수 추가 |
| 개인정보 미표시 | 5.1.1 | 개인정보 처리방침 필수 |
| 백그라운드 위치 무단 | 5.1.1 | 정확한 목적 설명 |
| 외부 결제 유도 | 3.1.1 | 인앱결제만 사용 |
| 웹뷰만 있는 앱 | 4.2 | 네이티브 기능 포함 |
| 스팸/복제 앱 | 4.3 | 고유 가치 제공 |
| 테스트 계정 미제공 | - | 로그인 필요 시 제공 |

### 4.2 Google Play 흔한 리젝 사유

| 사유 | 방지 방법 |
|------|-----------|
| 개인정보처리방침 없음 | URL 입력 필수 |
| 데이터 보안 미완료 | 설문 완료 필수 |
| 콘텐츠 등급 미완료 | 설문 완료 필수 |
| 권한 과다 요청 | 필요한 권한만 요청 |
| 허위 광고 | 메타데이터 정확하게 |
| 기능 미작동 | 모든 기능 테스트 |
| 아동 대상 정책 위반 | 타겟층 정확하게 설정 |

### 4.3 심사 전 체크리스트

**제출 전 필수 확인:**

- [ ] 앱이 크래시 없이 실행됨
- [ ] 모든 버튼/링크가 작동함
- [ ] 로그인/로그아웃 정상 작동
- [ ] 인앱결제 테스트 완료 (해당 시)
- [ ] 개인정보처리방침 접근 가능
- [ ] 스크린샷이 현재 앱과 일치
- [ ] 설명이 실제 기능과 일치
- [ ] 테스트 계정 준비 (필요 시)
- [ ] 심사 참고 사항 작성 (특별 설명 필요 시)

## 5. ASO 최적화

### 5.1 키워드 전략

**iOS 키워드 (100자)**

```
투두,할일,체크리스트,일정,task,todo,계획,생산성,목표
```

팁:
- 쉼표로 구분, 공백 없이
- 앱 이름에 있는 단어 제외 (중복 불필요)
- 경쟁 키워드 + 틈새 키워드 조합
- 단수/복수 중 하나만 (자동 인식)

**Android 설명 최적화**

- 첫 80자에 핵심 키워드 포함
- 자연스러운 문장으로 키워드 삽입
- 불렛 포인트로 기능 나열
- 리뷰 키워드 활용

### 5.2 스크린샷 최적화

**구성 권장:**
1. 핵심 가치 전달 (첫 번째)
2. 주요 기능 1
3. 주요 기능 2
4. 차별화 기능
5. 소셜 프루프 (리뷰, 수상 등)

**디자인 팁:**
- 기기 프레임 사용
- 간결한 캡션 추가
- 브랜드 색상 일관성
- 밝고 깨끗한 배경

### 5.3 전환율 최적화

| 요소 | 영향도 | 최적화 방법 |
|------|--------|-------------|
| 아이콘 | ★★★★★ | A/B 테스트, 경쟁사 분석 |
| 스크린샷 | ★★★★☆ | 첫 2장이 핵심 |
| 앱 이름 | ★★★★☆ | 키워드 포함 |
| 평점 | ★★★★☆ | 리뷰 관리, 앱 품질 |
| 설명 | ★★★☆☆ | 첫 문장이 핵심 |

## 6. 출시 후 체크리스트

### 6.1 출시 직후 (D-Day)

- [ ] 앱스토어에서 검색 확인
- [ ] 다운로드 및 설치 테스트
- [ ] 결제 기능 실제 테스트 (해당 시)
- [ ] 크래시 모니터링 대시보드 확인
- [ ] 랜딩페이지 링크 확인

### 6.2 출시 후 1주일

- [ ] 사용자 리뷰 확인 및 응답
- [ ] 크래시 리포트 분석
- [ ] 핵심 지표 확인 (DAU, 리텐션)
- [ ] 긴급 버그 수정 (필요 시)
- [ ] 첫 주 마케팅 성과 분석

### 6.3 출시 후 1개월

- [ ] 리뷰 트렌드 분석
- [ ] 기능 사용 데이터 분석
- [ ] 업데이트 계획 수립
- [ ] ASO 키워드 최적화
- [ ] 경쟁사 모니터링

## 부록: 빠른 참조

### Fastlane 명령어

```bash
# iOS 빌드 & 업로드
bundle exec fastlane build_and_upload_ios

# Android 빌드 & 업로드
bundle exec fastlane build_and_upload_android

# 스크린샷 자동 생성
bundle exec fastlane generate_screenshots

# 메타데이터 업로드 (소스: <root>/metadata/)
bundle exec fastlane upload_metadata

# 버전 증가
bundle exec fastlane bump_version type:patch
```

### 필수 URL 체크리스트

- [ ] Privacy Policy: `https://your-domain.com/privacy-policy.html`
- [ ] 지원 페이지: `https://your-domain.com` 또는 이메일
- [ ] 마케팅 페이지: `https://your-domain.com` (선택)

### 연락처 정보

App Store Connect & Google Play Console 모두 필요:
- 담당자 이름
- 이메일 주소
- 전화번호 (iOS 필수)
